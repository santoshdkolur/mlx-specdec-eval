# Speculative Decoding Mathematical & Theoretical Foundations

This document details the mathematical theory, probability bounds, performance models, and metrics calculated by `mlx-specdec-eval`.

---

## 1. Speculative Decoding Mechanics

Speculative Decoding addresses the memory-bandwidth bottleneck of auto-regressive LLM inference on Apple Silicon. Auto-regressive generation requires reading all model weights from Unified Memory for every single token generated.

### Algorithm Summary
1. **Draft Step:** A small, fast Draft Model ($M_D$) auto-regressively predicts $K$ candidate tokens $[x_1, x_2, \dots, x_K]$.
2. **Verification Step:** A large, high-quality Target Model ($M_T$) processes the prompt plus all $K$ candidate draft tokens in a **single parallel forward pass**.
3. **Rejection Sampling:** The probability distributions $P_T(x)$ and $P_D(x)$ are verified using rejection sampling to preserve exact sample distribution equivalence to $M_T$.

---

## 2. Rejection Sampling & MLX Verification Mechanics

For each draft token $x_i$ proposed by $M_D$, a standard speculative decoding verification step accepts $x_i$ using a probabilistic rejection sampling policy:

$$P_{\text{accept}}(x_i) = \min\left(1, \frac{P_T(x_i)}{P_D(x_i)}\right)$$

If token $x_i$ is rejected, all candidate tokens from position $i+1$ to $K$ are discarded, and a replacement token is drawn from the adjusted target probability distribution:

$$P_{\text{corrected}}(x) = \max\left(0, P_T(x) - P_D(x)\right)$$

### MLX Implementation Detail
In the `mlx-lm` framework, verification is implemented as a **greedy token equality check**:
- If `target_token == draft_token` $\rightarrow$ Draft token accepted.
- If `target_token != draft_token` $\rightarrow$ Draft token rejected; target model's generated token is substituted immediately, and all subsequent draft tokens in the current round are discarded.

For greedy decoding ($T = 0.0$), this implementation is mathematically equivalent to the original paper's probabilistic rejection sampling algorithm.

### Output Equivalence
- **Greedy Decoding ($T=0.0$):** In greedy mode, speculative decoding produces output identical to running Target Model $M_T$ alone ($EM = 1.0$).

## 3. Mathematical Metrics & Tracking Mechanics

In `mlx-specdec-eval`, this metric is computed using a state machine that processes the token stream yielded by the MLX `stream_generate` generator. This design accounts for two key aspects of how MLX exposes speculative decoding outputs:

#### 1. Semantic Meaning of `from_draft`
The `from_draft` boolean flag returned for each token chunk indicates whether the token was generated by the draft model and validated by the target model:
* **`from_draft = True`**: The draft model proposed this token, and the target model verified it as correct.
* **`from_draft = False`**: The token was generated directly by the target model. This occurs at the boundary of every speculative round in two cases:
  1. **Mismatch Correction**: The draft model proposed an incorrect token. The target model discarded the incorrect proposal and all subsequent draft tokens in that round, substituting its own corrected token instead.
  2. **Step Completion (Bonus Token)**: The draft model successfully predicted all $K$ tokens. The target model accepted all of them, and then used the remaining capacity of its parallel forward pass to generate one additional "bonus" token (the $K+1$-th token) for free.

Because a `from_draft = False` token is emitted at the end of *every* round regardless of whether the round was a success or a failure, counting `from_draft = False` occurrences does not directly represent the number of rejected tokens.

#### 2. Implicit Discard Tracking
When the draft model makes an incorrect prediction, MLX immediately terminates the verification loop for that round and discards all remaining draft tokens in memory. These discarded tokens are never yielded to the generator stream and are completely invisible to the output loop. 

To track these lost tokens, the tracking engine calculates them implicitly using the difference between proposed and accepted counts:

$$\text{Discarded (Rejected) Tokens} = \text{Total Proposed} - \text{Total Accepted}$$

#### 3. State Machine Algorithm
To count the baseline parameters accurately without double-counting during a single parallel round, the engine uses the following state-machine loop:

```python
# Iterated for every token yielded by stream_generate
if not in_draft_step:
    # A new speculative round has started.
    # Track the number of candidate tokens proposed in this step.
    remaining = max_tokens - output_tokens
    proposed_this_step = min(remaining, num_draft_tokens)
    total_draft_tokens_proposed += proposed_this_step
    
    # Lock the round so subsequent tokens in this batch do not increment the count
    in_draft_step = True

if chunk.from_draft:
    # Target model verified and accepted this draft token
    accepted_draft_tokens += 1
else:
    # Target model overrode a draft token OR emitted the round-end bonus token.
    # The speculative round is over; unlock the state machine for the next round.
    in_draft_step = False
```

- $\alpha \to 1.0$: Draft model predicts target tokens with high accuracy.
- $\alpha \to 0.0$: Draft model predictions are consistently rejected.

### B. Expected Tokens Per Verification Step ($E[\text{Tokens}]$)

Given draft token count $K$ and acceptance rate $\alpha$, the expected number of accepted tokens per verification step is:

$$E[\text{Tokens}] = \frac{1 - \alpha^{K+1}}{1 - \alpha}$$

When $\alpha \to 1$, $E[\text{Tokens}] \to K + 1$.

---

### C. Tokens Per Second (TPS)

Generation throughput is calculated during the **decode phase** (time from first generated token to completion), isolating generation speed from prompt prefill latency:

$$\text{TPS} = \frac{N_{\text{generated\_tokens}}}{T_{\text{decode\_time}}}$$

- **Decode Latency ($T_{\text{decode\_time}}$):** Measured from timestamp of initial token yield ($n=0$) to final token yield.
- **Total TPS (Inclusive of Prefill):** Also recorded for full profiling transparency as $\text{Total TPS} = \frac{N_{\text{generated\_tokens}}}{T_{\text{elapsed\_total}}}$.


---

### D. Speedup Factor ($S$)

The speedup ratio compares speculative generation throughput to baseline target generation:

$$S = \frac{\text{TPS}_{\text{speculative}}}{\text{TPS}_{\text{baseline}}}$$

- **$S > 1.0\times$**: Effective acceleration achieved.
- **$S = 1.0\times$**: Break-even point.
- **$S < 1.0\times$**: Overhead of running $M_D$ exceeds parallel verification gains.

---

### E. Task Domain Breakdown ($S_{\text{domain}}$)

Per-category metrics are evaluated dynamically across task domains $C \in \{\text{CODE}, \text{REASONING}, \text{CHAT}, \text{PROSE}\}$:

$$\alpha_{\text{domain}} = \frac{\sum_{j \in C} \text{AcceptedTokens}_j}{\sum_{j \in C} \text{DraftTokens}_j}$$

$$S_{\text{domain}} = \frac{\text{TPS}_{\text{speculative, domain}}}{\text{TPS}_{\text{baseline, domain}}}$$

---

## 4. Apple Silicon Unified Memory Tradeoff Equation

On Apple Silicon (M1/M2/M3/M4), GPU and CPU share Unified Memory. The memory bandwidth required per step is:

$$\text{Bandwidth}_{\text{speculative}} = \text{Size}(M_D) \times K + \text{Size}(M_T)$$

For speculative decoding to achieve speedup $S > 1.0\times$, the following inequality must hold:

$$\frac{\text{Size}(M_D)}{\text{Size}(M_T)} \times K + \frac{T_{\text{overhead}}}{T_{\text{target\_step}}} < \alpha \times K$$

`mlx-specdec-eval` parameter sweeps identify the optimal $K$ value where speedup $S$ is maximized on a given Mac configuration.

---

## 5. Adaptive $K$ Mathematical Formulation

When token predictability fluctuates across responses, static $K$ results in either under-speculation ($\alpha \approx 1$) or over-speculation ($\alpha \approx 0$). Adaptive $K$ modulates $K_t$ dynamically.

### A. Round Acceptance & EMA Formulation

At round $t$, given current depth $K_t$ and accepted draft tokens $n \in [0, K_t]$:

$$\alpha_{\text{round}} = \frac{n}{K_t}$$

The historical acceptance rate is updated via Exponential Moving Average (EMA) with smoothing factor $\beta \in [0, 1]$:

$$\alpha_{\text{EMA}}^{(t)} = \beta \cdot \alpha_{\text{EMA}}^{(t-1)} + (1 - \beta) \cdot \alpha_{\text{round}}$$

### B. Dynamic Transition Policy

The depth for round $t+1$ is adjusted dynamically:

$$K_{t+1} = \begin{cases} \min(K_t + 1, K_{\max}) & \text{if } n = K_t \text{ or } \alpha_{\text{round}} \ge 0.75 \\ \max(K_t - 1, K_{\min}) & \text{if } n = 0 \text{ or } \alpha_{\text{round}} \le 0.33 \\ K_t & \text{otherwise} \end{cases}$$

### C. Mean Effective Speculation Depth ($\bar{K}$)

$$\bar{K} = \frac{1}{R} \sum_{r=1}^{R} K_r$$

### D. Wasted Draft Ratio ($\text{WDR}$)

$$\text{WDR} = \frac{N_{\text{proposed}} - N_{\text{accepted}}}{N_{\text{total\_generated}}}$$
